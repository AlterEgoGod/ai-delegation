# Приёмка и расходы

## Приёмка Astra

- Сопоставь результат с исходными требованиями.
- Посмотри фактический diff и связанный код, проверь границы изменений.
- Проверь, что тесты отражают нужное поведение, а не подстроены под реализацию.
- Изучи реальные результаты проверок. При недостаточных доказательствах выполни проверку самостоятельно.
- Повторяй проверки при изменении соответствующего кода, среды или при сомнении в предыдущем результате.
- Верни конкретные замечания с критерием исправления. Одна попытка исправления тем же исполнителем; затем повышение уровня или работа Astra.
- Сообщи о проверках, которые не удалось выполнить. Не объявляй такую задачу полностью проверенной.

## Оценка эффективности

Для репрезентативных задач сравнивай прямую работу Astra и делегирование по одинаковым критериям приёмки. Учитывай постановку, работу всех исполнителей, повторные попытки и проверку главного агента. Фиксируй фактические модели, расход (если доступен), время и принятый результат.

Более дешёвая модель может потребовать больше токенов и исправлений. Не обещай снижение числа токенов или стоимости без измерений. Если тип задач систематически дороже при делегировании, предложи отдельное изменение политики; не редактируй её самостоятельно.
