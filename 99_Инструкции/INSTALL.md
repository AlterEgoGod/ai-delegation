# Установка из Git

## Требования

Git, Python 3.11+ (стандартная библиотека), локальный Codex с поддержкой пользовательских агентов. Для Windows есть оболочка PowerShell; на Linux/macOS запускайте install.py напрямую. Нужен доступ на чтение репозитория. Установщик не устанавливает Python, Codex и не меняет глобальные настройки или разрешения.

## Отдельная установка

В корне существующего Git-проекта, выполняя команды по очереди:

```powershell
git submodule add https://github.com/AlterEgoGod/ai-delegation.git .ai-delegation
git -C .ai-delegation checkout --detach v1.0.0
python .ai-delegation/99_Инструкции/03_Установка/install.py --project .
python .ai-delegation/99_Инструкции/03_Установка/install.py --project . --check
git add .gitmodules .ai-delegation AGENTS.md .codex/config.toml .codex/agents .codex/ai-delegation.lock.json
git commit -m "Install ai-delegation v1.0.0"
```

Перед git add проверьте изменения: не включайте посторонние файлы из существующей .codex/agents. Путь .ai-delegation должен быть свободен. Если модуль уже подключён, используйте его, не добавляйте второй экземпляр. Метка v1.0.0 обозначает релиз; submodule и lock сохраняют фактический коммит.

Эквивалент запуска установщика в Windows:

```powershell
& ./.ai-delegation/99_Инструкции/03_Установка/install.ps1 -ProjectRoot .
```

## Через ai-rules

При подключённом ai-rules в папке .ai-rules:

```powershell
git submodule update --init --recursive
python .ai-rules/99_Инструкции/03_modules/01_ai-delegation/99_Инструкции/03_Установка/install.py --project .
python .ai-rules/99_Инструкции/03_modules/01_ai-delegation/99_Инструкции/03_Установка/install.py --project . --check
```

Сам репозиторий ai-rules использует тот же установщик с путём без префикса .ai-rules. Версия зависимости задаётся gitlink в ai-rules. Второй самостоятельный модуль устанавливать не нужно.

## Что изменяется

- В AGENTS.md добавляется один блок со ссылкой на локальный RULES.md.
- В .codex/config.toml добавляются отсутствующие настройки Astra и субагентов. Остальные параметры и комментарии сохраняются.
- В .codex/agents появляются три конфигурации delegation-*-worker.toml.
- В .codex/ai-delegation.lock.json сохраняются относительный путь, коммит и контрольные суммы.

Контрольные суммы нормализуют CRLF в LF, чтобы обычное клонирование Git на Windows не выглядело изменением правил.

Установка идемпотентна: повторный запуск без изменений не переписывает файлы. Все конфликты проверяются до записи. При ошибке записи установщик пытается вернуть уже изменённые файлы. Он не поддерживает одновременную установку двумя процессами; не редактируйте эти файлы во время установки.

Если существующая модель, лимит или другая управляемая настройка отличается, установщик останавливается с именем конфликтующего параметра. Согласуйте это конкретное изменение, вручную объедините настройки и повторите запуск. Изменённые пользователем роли не перезаписываются. При AGENTS.override.md требуется отдельное согласованное объединение входных инструкций. Источник должен быть закоммичен и находиться внутри целевого проекта; рабочая копия с изменениями не устанавливается.

## Активация и проверка моделей

1. Откройте новую сессию Codex в корне проекта. Проект должен быть доверенным; установщик не назначает доверие автоматически.
2. Проверьте выбранную основную модель: GPT-6 Astra. Настройки интерфейса, CLI и администратора могут иметь более высокий приоритет.
3. Проверьте доступные модели в интерфейсе Codex. Установщик --check проверяет файлы, а не права аккаунта на модели.
4. На первой подходящей реальной задаче попросите применить правила делегирования и показать фактическую модель исполнителя. Главный агент должен проверить результат. Нельзя объявлять все роли проверенными по одному успешному запуску.
5. Если модель недоступна, применяется явная замена по RULES.md. Расходы и доступность не выдумываются.

Для проверки схемы настроек без вызова модели можно использовать CLI, поддерживающий --strict-config. Проверка схемы не доказывает применение проектных настроек или доступность модели.

## Работа на другом компьютере

```powershell
git clone --recurse-submodules <URL_ПРОЕКТА>
```

В существующей копии выполните git submodule update --init --recursive до запуска агента. Если конфигурации и lock закоммичены вместе с проектом, повторная установка не нужна; выполните --check.

## Обновление

По отдельному поручению перейдите на новый проверенный коммит submodule, запустите установщик повторно и --check, просмотрите diff, сохраните новый gitlink и lock. Не используйте update --remote в обычной работе. При подключении через ai-rules обновляйте зависимость в ai-rules, затем закреплённую версию ai-rules в проектах. Запрещено перемещать опубликованные релизные теги.

## Удаление

Просмотрите diff относительно состояния до установки. Удалите только блок между ai-delegation:begin/end, неизменённые файлы delegation-*-worker.toml и lock. В config.toml восстановите прежние значения только управляемых параметров. Затем отдельно отключите submodule стандартными средствами Git. Не удаляйте весь AGENTS.md, .codex/config.toml или каталог .codex/agents: там могут быть другие настройки. Автоматическое удаление в этой версии не предусмотрено.
